USER ROLES & PERMISSIONS:
GECAN Admin: Full CRUD access on all data. Manages users, vetting, approvals, platform settings, can view all offers/enquiries/matches. Accesses internal dashboards.
Vetted Member (Buyer/Seller/Broker etc.):
Can submit their specific Offers (if Seller) or Enquiries (if Buyer).
Can view/manage their own submissions.
Can search/view anonymized or summarized details of Active, matching Offers/Enquiries (details revealed upon GECAN-facilitated introduction).
Can access relevant Toolkits, Community Hub, Knowledge Base.
Access level potentially tiered based on verificationLevel or performance history (future).
Pending Verification User: Limited access. Can complete profile/application, upload DD documents. Cannot submit offers/enquiries or view market data until approved by Admin.
Public/Unauthenticated: Access only to a potential landing page (if desired) and login/registration prompts.
CORE FEATURE BREAKDOWN:
Authentication & Onboarding:
Secure user registration requiring initial details (email, name, company).
Email verification step.
Login with secure password handling (hashing, salting).
Post-login: Users land in 'Pending Verification' status. They are prompted to complete a detailed profile/application form (mirroring KYC/CDD requirements from 00_TEMPLATES/01_Legal_Compliance_Templates/KYC_CDD/).
Interface for uploading necessary DD documents (securely handled, links stored in DueDiligenceRecords).
GECAN Admin Vetting Workflow:
Admin dashboard showing 'Pending Verification' users.
Interface to review submitted profiles and documents.
Ability to request more information from the user.
Internal checklist tracking (DueDiligenceRecords).
Functionality to 'Approve' (sets User role to 'Vetted_Member', assigns gecanMemberId, sets verificationLevel) or 'Reject' user applications.
Seller Offer Management:
Submission: Vetted Sellers access a dedicated "Create New Offer" section. A dynamic form (similar to the refined ClientScript.html logic) loads based on the selected offerType ('GOLD', 'BTC', etc.). Form fields must match the database schema / Google Sheet columns for that type. Input validation (required fields, data types) client-side and server-side.
Admin Approval: Submitted offers enter 'Pending Approval' status. GECAN Admins review the offer details for clarity, plausibility, and compliance. Admins can approve (sets status to 'Active'), reject, or request clarification.
Seller View: Sellers can view/manage their submitted offers (view details, potentially edit before approval or if inactive, request archival).
Display: Active offers become potentially visible (in summarized/anonymized form) in search results for relevant, vetted Buyers.
Buyer Enquiry Management:
Submission: Vetted Buyers access "Create New Enquiry". Dynamic form based on enquiryType. Fields capture specific requirements. Validation applied. Enquiries enter 'Submitted' or 'Pending Review'.
Admin Review: Admins review enquiries for clarity and legitimacy. Approve to 'Active' status.
Buyer View: Buyers manage their enquiries.
Display: Active enquiries become potentially visible to relevant, vetted Sellers.
Search & Discovery:
Central search interface for Vetted Members.
Filter by offerType/enquiryType, status, potentially location, quantity ranges, keywords.
Display results in a clean, sortable table/card view. Show limited, non-identifying details initially (e.g., Offer Type, Quantity Range, Location Region, Status, GECAN Offer ID). Full details only revealed after GECAN facilitates a match/introduction.
Matching Engine (v1.0 - Admin Facilitated):
Internal: GECAN Admins use enhanced search/filtering tools to identify potential matches between Active Offers and Active Enquiries based on key criteria (Commodity Type, Quantity, Location, Incoterm, Price/Rate expectations, Status etc.).
Introduction Workflow: Admin initiates an introduction process (logs in Matches table). This could trigger notifications (future) or simply allow the Admin to securely share contact details/full offer/enquiry details between the matched parties after confirming mutual interest. v1.0 does not require automated matching; focus on enabling Admin search and tracking facilitated matches.
Archiving:
Automated process (e.g., nightly batch job or triggered check) to set status to 'Expired' for offers past their expiryDate.
Manual option for Admins (and potentially Sellers for their own offers) to set status to 'Archived' or 'Invalid'.
Archived/Expired offers are excluded from default searches but potentially viewable via specific filters or in historical records for Admins.
